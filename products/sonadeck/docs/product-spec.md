# SonaDeck 首期产品需求

更新日期：2026-09-23。状态：规划草案。名称与核心目标由用户确认；以下首期拆分和验收要求为实施建议。

## 1. 产品承诺

用户可以把多个应用的音量、静音和输出选择保存为一套配置，在主界面点击一次完成场景切换，并知道哪些设置已经生效、哪些尚未生效。

“整套”指配置明确管理的全部字段，并非接管 Mac 所有声音设置。产品同时提供日常手动控制，不要求用户先建立配置才能使用。

## 2. 目标用户与任务

首期面向经常在耳机、扬声器、USB 音频设备之间切换，且同时使用多个有声应用的 Mac 用户。先验证个人办公与娱乐场景，不承诺专业录音工作站的时延或设备同步能力。

| 任务 | 示例 | 成功表现 |
| --- | --- | --- |
| 从日常切到会议 | 浏览器静音、会议应用音量调到预设值、输出指向耳机；可选调整系统默认输入 | 主界面一次点击；实际路由与状态可检查 |
| 从会议切回音乐 | 音乐应用输出 USB DAC，浏览器降低音量，解除之前由配置设置的临时静音 | 配置切换不会残留旧场景的控制 |
| 保存自己的环境 | 调好应用与设备，保存为“夜间”，稍后恢复 | 重启后配置仍在；设备缺失时解释清楚 |

会议应用可能自选输入和输出，系统默认输入变更不代表会议应用一定跟随。UI 必须反映这个边界。

## 3. 首期必须具备

| ID | 能力 | 边界 / 验收 |
| --- | --- | --- |
| F01 | 音频应用列表 | 显示可识别的有声应用；可添加未运行的已安装应用；浏览器按应用聚合，不按标签页 |
| F02 | 每应用音量与静音 | 软件增益范围 0–100%，不做超额放大；显示静音与音量的不同状态；调节不改变其他应用 |
| F03 | 每应用输出选择 | 一应用选一个输出，或跟随系统默认；至少内置、USB、蓝牙输出进入验证矩阵 |
| F04 | 系统设备快捷控制 | 切换默认输出；对有可写音量能力的设备调节硬件音量；可选配置默认输入，不捕获麦克风 |
| F05 | 多套配置管理 | 新建、从当前状态保存、编辑、另存为、重命名、复制、排序、删除；建议至少验证 20 套配置 |
| F06 | 主界面整套切换 | 常用配置始终可见，一次点击应用；长列表通过列表或搜索访问；不能只有设置页入口 |
| F07 | 清晰的真实状态 | 区分生效、应用未运行、配置已修改、设备缺失、切换中、失败与恢复失败 |
| F08 | 持久化与恢复 | 配置写入失败不显示保存成功；旧版本迁移、损坏恢复、退出与崩溃后的音频恢复进入验收 |
| F09 | 菜单栏入口 | 打开主窗口、选择配置、查看当前状态；关闭主窗口后音频控制继续运行，明确提供“退出” |
| F10 | 基本设置与可访问性 | 用户自选登录启动；英文与简体中文；深浅色、键盘、VoiceOver、减少动态效果 |

F01–F10 是首期发布门槛；验证中发现不可行时记录结果并重新裁定范围，不能悄悄标为完成。

## 4. 本期暂缓

- EQ、Audio Unit 插件、响度增强、耳机补偿和其他 DSP 效果器。
- 同一应用同时输出到多个设备、AirPlay 网络播放、专业多通道音频与设备时钟同步。
- 每应用输入路由、麦克风处理、录音、转写、浏览器标签页独立控制。
- 按时间、设备接入或应用状态自动切换场景；快捷指令集成和全局配置快捷键。
- 云同步、账号系统、配置社区、Windows / iOS 版本。
- AI 对话、智能推荐、自动生成音频配置及相关模型服务。

后续重新规划这些能力时，应基于首期反馈单独评估，不为其预先加入依赖。

## 5. 交付形态

原生 Mac 主窗口 + 菜单栏快捷入口。主窗口是完整操作面板，菜单栏是快速入口。首次使用解释系统音频访问用途，按需触发系统授权；权限拒绝时仍可查看和编辑本地配置。

核心功能离线可用，首期不依赖账号。收费方式、试用、价格、许可服务与商店内购在发布准备阶段决定，不影响技术原型验证。

## 6. 价值验证

先招募约 5–8 位确有多场景切换需求的用户，在其真实设备上完成相同任务。比较手动操作、现有工具和 SonaDeck 的耗时、错误次数、设备缺失时的理解程度，以及是否愿意继续使用。反馈收集需用户实际参与，当前未开展。

至少 4/5 位受测者应能在简短引导后独立保存并切换两套配置；不理解当前声音去哪、误以为切换成功的情况必须修正。这是可用性目标，不是市场需求已被证明。

“有预设”不是已验证的独有卖点。首期重点验证能否把真实切换过程做得更少步骤、更可靠、更容易理解。

## 7. 发布完成条件

F01–F10 与 [配置语义](profiles.md)通过对应测试；[验证计划](validation.md)中的支持矩阵、恢复与体验门槛通过；真实用户能完成核心任务；分发安装路径可重现；不存在已知导致持续无声、错误路由或配置丢失的阻断问题。
