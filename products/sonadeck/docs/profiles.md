# 配置模型与切换语义

更新日期：2026-09-23。状态：拟定的产品与实现契约，待原型验证。

## 1. 用户看到的对象

- **已保存配置**：明确保存的目标设置，切换时以它为准。
- **当前实际状态**：从系统与音频引擎读取的状态，不通过按钮选中状态推断。
- **临时调整**：在当前配置上调音量或改路由，不自动覆盖已保存配置。
- **切换前快照**：仅用于恢复这次切换所修改的设置，不是另一套用户配置。

主界面显示“工作”“工作 · 已修改”或“音乐 · 切换未完成”，避免只显示一个看似成功的配置名。

## 2. 建议的数据结构

采用本地带 `schemaVersion` 的 Codable 数据文件，原子替换写入并保留一份最近有效备份。实际文件位置由沙盒与分发路线决定，不硬编码家目录路径。

| 对象 | 主要字段 | 规则 |
| --- | --- | --- |
| Profile | id、name、revision、createdAt、updatedAt、sortOrder | id 稳定；修改保存时增加 revision |
| SystemSettings | 可选 defaultOutput、defaultInput、outputVolume | 字段未设置表示不接管；音量须绑定实际设备身份 |
| AppRule | appIdentity、gain、muted、outputTarget | gain 为 0–1；每套配置每应用一条规则 |
| AppIdentity | bundleIdentifier、显示名、可选来源标识 | 不持久化 PID；辅助进程归属由运行时解析 |
| OutputTarget | followSystem 或 specificDevice(deviceUID) | UID 为首选身份；显示名只用于展示和人工重绑定 |
| RuntimeState | activeProfileID、revision、observedState、overrides、pendingRules | 单独存储；运行时变化不直接写回配置 |
| Transition | transitionID、旧快照、目标 revision、逐项结果 | 用于串行执行、过期回调识别与恢复 |

没有稳定应用身份时，不以同名应用自动匹配。设备 UID 改变或名称重复时，要求用户在 UI 中重新绑定，不能凭显示名猜测。

`outputVolume` 仅控制有可写硬件音量的目标设备；不支持的 HDMI / DAC 等设备显示能力限制，首期不隐式增加系统级软件音量替代层。

## 3. 保存与手动修改

1. “保存为配置”捕获用户确认纳入管理的应用及系统字段，保存前预览；没有选择的设置不接管。
2. 手动调节立即作用于运行态，标记“已修改”。“保存”覆盖当前配置，“另存为”创建新配置，“恢复已保存设置”重新应用当前配置。
3. 用户切换到其他配置时，不弹出每次都要确认的对话框；旧临时调整存为可恢复草稿，目标配置仍按其已保存内容执行。再次选择旧配置也先执行已保存版本，恢复草稿须显式操作。
4. 配置编辑器中的字段修改先形成草稿；保存后不偷偷改变当前音频，提供明确的“保存并应用”。
5. 删除当前配置仅删除模板，现有音频保持，状态改为“自定义”；删除操作支持短期撤销。

## 4. 一次切换的流程

```text
选择目标
  → 校验配置、权限、设备及能力
  → 获取切换前快照并生成执行计划
  → 准备新路由与音量参数
  → 按依赖顺序应用变更
  → 回读系统状态与引擎状态
  → 生效 / 等待应用启动 / 失败并尝试恢复
```

这是协调多项操作的过程，不宣称系统提供真正的原子事务。

- **预检失败**：目标明确指定的设备离线、必需权限缺失或字段不可写时，默认不执行任何目标变更；指出阻塞项并提供编辑入口。
- **准备与应用**：先准备可用输出，使用短增益斜坡避免突变；具体静音、路由建立和旧路径释放顺序由 M0 实测决定。不能为了动画延迟音频执行。
- **读回确认**：可读系统字段比较实际值；软件增益确认对应引擎参数已提交。没有端到端测量时，不能声称已自动确认扬声器实际出声。
- **执行失败**：取消剩余动作，恢复本次已修改且仍由本次操作控制的字段；发现用户或其他程序同时修改时，不盲目覆盖，显示冲突与实际结果。
- **恢复失败**：列出仍不一致的字段，提供重试及“停止 SonaDeck 控制”入口；保持可操作，不循环重试抢占系统。

## 5. 应用、设备和规则的边界

| 情况 | 首期行为 |
| --- | --- |
| 配置中的应用未启动 / 暂无可绑定音频进程 | 保留规则并显示“待应用发声”；其他可执行项成功后显示“已应用 · N 项待生效” |
| 应用稍后启动或辅助进程重建 | 只绑定当前配置 revision 的有效规则；不能让旧场景回调覆盖新场景 |
| 新配置不再包含旧配置管理的应用 | 移除旧规则，释放旧控制；软件增益回到单位增益，路由回到该应用原有行为；不改应用自身音量 |
| 系统字段在新配置中缺省 | 不继续接管；若仍等于 SonaDeck 上次写入值，恢复进入连续配置会话前记录的原值；若外部已改，保留外部值并提示 |
| 不在任何配置中的新应用 | 保持原行为，直到用户明确控制或添加到配置 |
| 目标配置设备缺失 | 预检阻止整套切换，不静默改播扬声器；手动选择替代设备后重试 |
| 已生效期间设备断开 | 尝试暂停受影响的处理流并显示缺失；不主动改播其他设备。系统或源应用可能自行回退，必须验证并披露能否阻止 |
| 设备重新连接 | 显示可恢复状态，首期由用户点击重新应用；不突然自动切回 |
| 系统默认输出变化 | followSystem 规则跟随；固定设备规则保持固定，重建失败则显示异常 |
| 用户在系统设置中改音量 / 输出 | 更新实际状态并标记偏离，不持续自动写回抢占控制 |
| 用户连续选择 A → B → C | UI 立即响应；音频变更单通道串行，尚未开始的目标合并为最后一次。已开始的步骤到安全边界后再重算 C |
| 重复点击当前配置 | 无变化则幂等；存在临时调整时重新应用已保存配置，临时调整保留为草稿 |

所谓“整套”不能导致旧配置里独有的静音、增益或路由永远残留；规则释放与系统字段恢复必须有独立测试。

## 6. 状态表达

| 状态 | 显示 | 允许操作 |
| --- | --- | --- |
| Ready | 当前实际设置 / 尚未选择配置 | 手动控制、保存、选择配置 |
| Applying | 正在切换到会议… | 可选择下一目标；冲突控件暂不可写 |
| Active | 会议 · 已应用 | 调整、保存、切换 |
| ActiveWithPending | 会议 · 2 项待应用发声 | 查看待生效项、切换 |
| Modified | 会议 · 已修改 | 保存、另存为、恢复、切换 |
| Blocked | 音乐未应用：USB DAC 未连接 | 修改目标、连接设备、重试 |
| Failed / RecoveryFailed | 切换失败，已恢复 / 有设置未恢复 | 查看逐项结果、重试、停止控制 |

ActiveWithPending 不等于失败，也不等于所有应用已经出声；文案必须保留这个区别。

## 7. 启动、退出与持久化

- 首次启动默认不自动接管。重新启动可提示恢复上次配置；“启动时恢复上次配置”由用户开启，并执行完整预检。
- 关闭窗口只隐藏界面，菜单栏和控制继续；“退出 SonaDeck”清理自身 tap、聚合设备及处理资源，并按所有权规则恢复可恢复字段。
- 崩溃或强制退出后释放 tap 是否恢复源音频是 M0 必测项，不能以正常退出表现替代。恢复失败是发布阻断项。
- 配置写入成功后才提示已保存。保留最近有效备份，迁移前备份；遇到更高 schemaVersion 只读并解释，不能覆盖成旧格式。
- 进程 ID、AudioObjectID 等运行期标识不可跨重启复用；快照记录只辅助恢复，不能据此盲写已经变化的系统状态。
