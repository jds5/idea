# 首期开发路线图

更新日期：2026-09-23。状态：M1 的跨平台领域基础已开始；M0 真机门槛尚未执行。

## 1. 执行原则

音频技术验证先于完整产品实现。范围以 [产品需求](product-spec.md)为准，整套配置切换是首期主线；不通过增加 EQ、自动化或 AI 掩盖基础控制的稳定性问题。

以下为一名已有 Swift / macOS 经验的开发者全职投入的粗估，假设能取得 Mac 与测试设备，M0 不需自研驱动。约 **9–14 个开发周**，另留 2–4 周兼容与外部流程缓冲；不是承诺日期。若需要学习底层音频或引入驱动，应在 M0 后重新估算。

## 2. 阶段与退出条件

| 阶段 | 估算 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| M0 技术可行性 | 1–2 周 | 最小双应用 / 双输出原型、权限与沙盒报告、故障恢复记录 | 真机证明音量、静音、路由及强制退出恢复；明确版本与分发候选；不可行则重新评估，不进入完整开发 |
| M1 领域与界面原型 | 1–2 周 | 配置模型、状态机、fake backend、主窗口和菜单栏交互原型 | 保存与切换流程走通；异常状态可演示；领域关键语义有测试 |
| M2 音频纵向实现 | 2–3 周 | 真实应用列表、增益、静音、单应用输出、设备快捷控制 | F01–F04 在声明的基础设备上可用，退出恢复可靠；UI 不阻塞音频 |
| M3 完整配置闭环 | 2 周 | 多配置持久化、主界面一键应用、草稿、回读、失败恢复 | F05–F08；连续切换、迟到应用、设备丢失、旧规则释放通过 |
| M4 Mac 体验与兼容 | 2–3 周 | 键盘与无障碍、本地化、动画、跨版本 / 设备回归 | F09–F10；性能预算和支持矩阵通过；无持续无声、错误路由或数据丢失缺陷 |
| M5 内测与发布准备 | 1–2 周 | 真实用户反馈、签名安装包、帮助与恢复说明、发布候选 | 核心任务可独立完成；问题分级清零；渠道、商业模式和名称检查完成 |

部分 M1 文档、跨平台领域基础与低保真交互可以在 M0 期间推进，但完整音频后端与最终 UI 打磨不能跳过 M0 结论。商店等待时间和用户招募时间不保证包含在开发估算内。

## 3. 第一批可执行任务（M0）

全部为待办。每项实验记录系统 / build、Mac 型号、设备、签名、命令、预期、实际结果和可复现步骤。

- [ ] **SD-001 环境基线**：选定 Mac 与稳定 Xcode；准备内置输出、USB DAC / 耳机、蓝牙耳机；记录实际系统版本。创建 `experiments/` 后再写可运行命令。
- [ ] **SD-002 进程与设备识别**：列出音频进程、应用归属、设备 UID 与能力；验证浏览器和 Electron 辅助进程，处理重名设备。
- [ ] **SD-003 单应用可控路径**：使用已知测试音频验证单位增益、约一半增益、静音、目标输出；证明无原始音频重复播放、无自捕获反馈。
- [ ] **SD-004 双应用双输出**：同时播放两个应用，分别控制音量并指向不同输出；记录采样率变化、CPU、内存、时延及失真现象。
- [ ] **SD-005 失败与释放**：设备拔出、权限撤回、源应用重启、SonaDeck 正常 / 强制退出、休眠唤醒；检查资源残留与恢复。
- [ ] **SD-006 沙盒对照**：同一核心测试在沙盒开 / 关构建执行，记录签名与权限差异，不以“捕获成功”替代完整路由成功。
- [ ] **SD-007 两套配置实验**：无需精美 UI，切换两套硬编码配置；一套含独有应用规则；证明切换后旧规则释放、重复点击幂等、缺设备不误报成功。
- [ ] **SD-008 技术决策**：汇总失败项、冻结最低实际系统版本与架构支持，选定后端及分发候选，更新 [决策记录](decisions.md)和估算。

M0 最低退出证据：两个应用在两个真实输出上完成 20 次往返切换，单位增益与静音无串扰，强制退出与热插拔有可重复恢复结果。此规模只用于可行性判断，不替代发布验收。

## 5. 风险与应对

| 风险 | 首先采取的行动 |
| --- | --- |
| tap 捕获成功但无法可靠静音 / 重定向 | M0 测完整输出链与释放；停止用 UI 进度掩盖技术缺口 |
| 浏览器 / 会议应用进程模型复杂 | 建兼容样本，明确不支持项，不承诺所有应用或标签页 |
| 蓝牙切换、设备时钟或采样率导致卡顿 | 单独测试输出与通话模式；将问题纳入发布支持范围决策 |
| 最新系统变化或沙盒限制 | 同一闭环跨版本 / 构建验证，尽早确定分发路径 |
| 快速切换造成竞态、旧规则回写 | 单一协调器、revision、取消边界和故障注入测试 |
| 只有“支持预设”不足以让用户迁移 | 用真实切换任务比较体验，记录愿意继续使用的原因 |

## 6. 完成记录

已完成：仓库结构、基础协作规则、首期需求、配置语义、体验方向、技术与验证计划；M1 每应用规则模型与切换计划器的第一段实现（见[开发与测试](development.md)）。

未完成：M0 全部真机实验、真实音频后端、系统字段和持久化、视觉原型、兼容性结论、真实用户测试、签名安装包和发布。

下一次进入工程阶段，从 SD-001 开始；下一次继续产品讨论，可以修改首期边界或细化主窗口设计。扩展功能与 AI 仍保持延后。
