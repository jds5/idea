# 真机验证与发布验收

更新日期：2026-09-23。状态：测试计划；下列项目均未执行，数字均为目标。

## 1. 测试层级

- **领域单元测试**：配置校验、差异、规则释放、切换状态机、并发目标合并、持久化迁移和故障恢复。使用可注入失败的 fake backend。
- **Mac 集成测试**：真实进程、权限、设备、tap 生命周期、音频路由、读回和退出恢复。
- **交互与性能测试**：主窗口和菜单栏同步、键盘 / VoiceOver、深浅色、动画帧、响应和资源占用。
- **真实任务内测**：用户在自己的设备上保存和切换配置，反馈实际用途与理解成本。

文档链接检查、跨平台逻辑测试、编译成功均不能替代真实音频和 UI 验收。

## 2. 系统与设备矩阵

版本策略以 [技术计划](technical-plan.md)为准。测试报告记录完整系统版本、build、架构、Xcode / SDK、应用 revision 和签名方式。

| 维度 | 发布前最低覆盖 |
| --- | --- |
| 系统 | 声明的最低 macOS 15 小版本，以及 macOS 26、27 的选定正式版本；每代覆盖基本闭环 |
| Mac | 至少一台作为低性能基线的 Apple Silicon Mac，建议 M1 / 8 GB；另一代机器补充回归 |
| 输出 | 内置扬声器 / 有线耳机、至少一种 USB 音频设备、至少一种蓝牙耳机 |
| 扩展输出 | HDMI / DisplayPort 验证设备选择和硬件音量不可写提示；多输出同步和 AirPlay 不在首期承诺 |
| 输入变化 | 内置麦克风与外接麦克风；检查会议应用是否跟随系统默认输入，明确自选输入的边界 |
| 音频格式 | 44.1 kHz、48 kHz、立体声；不支持格式明确显示而非静默失败 |
| 应用 | 本地播放器、Safari、Chrome / Electron、会议应用；受保护音频单列，不默认承诺支持 |
| 界面 | 60 Hz、可用时 120 Hz；深浅色、缩放、长应用名、20 套配置、20 行应用 |

基础矩阵覆盖每代系统的内置 + USB 闭环；当前系统执行完整设备矩阵；最低系统补测蓝牙、权限与退出恢复。未实际覆盖的组合在报告标注，不把抽样测试写成全组合通过。

## 3. 功能验收用例

| ID | 用例 | 预期 |
| --- | --- | --- |
| V01 | 两应用同时发声，单独调节 A、静音 A | B 不变；A 无重复播放；关闭静音保留原增益 |
| V02 | A 到 USB、B 到内置，改变系统默认输出 | 固定路由保持；followSystem 规则跟随；状态与实际一致 |
| V03 | 从当前设置保存两套配置，重启后再切换 | 持久化完整，应用身份不依赖旧 PID |
| V04 | A 配置含独有应用规则，切到不含该应用的 B | 旧静音、软件增益和路由控制释放，不残留 |
| V05 | 当前配置做临时调整，再切换其他配置 | 已保存内容不被覆盖；草稿可恢复；目标按已保存版本执行 |
| V06 | 目标设备缺失后点击配置 | 不执行目标变更；指出缺失；不静默改播其他设备 |
| V07 | 应用尚未运行，应用配置后再启动该应用 | 显示待生效；新进程只接收当前配置 revision 的规则 |
| V08 | 连续点击多套配置，注入迟到回调 | 最终以最后目标为准；无并发破坏、过期回写或资源持续增长 |
| V09 | 执行中注入设备写入失败 / 外部同时修改 | 按所有权恢复；冲突和恢复失败可见；不得显示整套成功 |
| V10 | 磁盘写入失败、配置损坏、旧 schema、新 schema | 不丢原文件；不假报保存；可恢复或只读解释 |
| V11 | 拒绝 / 撤回音频权限 | 界面可用，控制停止并解释；不反复弹窗或假装音频被控制 |
| V12 | 拔出设备、重新接入、休眠与唤醒 | 不崩溃、不无限重建；状态准确；能按说明恢复 |
| V13 | 正常退出、强制退出、模拟崩溃 | 无持续错误静音 / 音频循环；清理自身资源；验证系统回退行为 |
| V14 | 手动在系统设置改输出 / 音量 | 观察到变化并标记偏离，不与用户反复争抢设置 |
| V15 | 关闭主窗口，用菜单栏切换，再打开窗口 | 控制持续、状态一致；Command-Q 明确退出 |
| V16 | 仅用键盘和 VoiceOver 完成保存 / 切换 | 焦点、标签、数值和结果完整可理解 |

V06 / V12 / V13 要实际观察声音最终去了哪里。若无法阻止系统在耳机断开时回退扬声器，必须记录限制与界面说明，不能宣传“绝不外放”。

## 4. 性能与稳定性预算

以下作为 M0 校准起点；若必须调整，记录基线数据和用户影响，不在发布前静默放宽。

| 项目 | 初始验收目标 | 方法 |
| --- | --- | --- |
| 操作反馈 | 点击到可见响应 p95 ≤ 100 ms | signpost / Instruments 与交互录像 |
| 同输出配置切换 | 5 个已发声应用、仅增益 / 静音变化，回读完成 p95 ≤ 300 ms | 100 次往返；记录事件时间戳 |
| 已连接有线设备路由切换 | p95 ≤ 1 s，无死锁；蓝牙单独报告，不混入此口径 | 100 次，记录中断区间与失败率 |
| 同设备音量变化 | 无可闻爆音和非预期断续 | 已知波形记录 + 人耳复核；与旁路基线比较 |
| 处理增量时延 | 有线路径目标 ≤ 20 ms；不包含蓝牙自身时延 | 回环测量相对旁路基线的增加量，非只看 buffer 理论值 |
| 后台闲置 CPU | 目标平均 < 1% 单核口径（100% 为一核），稳定 10 分钟 | 固定基线机、关闭窗口、无受控活动流；记录系统噪声 |
| 典型运行资源 | 5 路立体声 / 48 kHz 平均 CPU < 5% 单核口径；物理内存占用目标 < 150 MB | Release 构建，定义一致的统计工具与口径；未达标定位原因 |
| 连续运行 | 8 小时混合使用无崩溃、持续无声或持续资源增长 | 起止资源、失败事件、设备变化日志 |
| 切换压力 | 1,000 次逻辑切换无残留规则 / 资源泄漏；至少 100 次真实设备切换 | fake 故障测试 + 真机分开记录 |
| UI 流畅度 | 按 [体验预算](experience.md)检查，不能有重复出现的明显主线程卡顿 | Instruments 分析滑杆拖动、列表和配置连续切换 |

0–100% 软件增益的数字与界面一致，硬件音量和声压并不线性等价；测量时使用已知信号并避免把百分比当作声压承诺。

## 5. 发布阻断条件

持续无声、音频反馈循环、错误输出且 UI 宣称正确、配置数据丢失、旧场景规则无法释放、失败假报成功、退出后无法按已验证流程恢复，以及支持矩阵中的稳定复现崩溃。

非阻断问题必须有明确范围和真实影响说明；不能以“Beta”标签替代核心可靠性门槛。
