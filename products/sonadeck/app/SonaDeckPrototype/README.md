# SonaDeck 原生 UI 测试原型

阶段：2026-10-09 经用户授权新增的最小 SwiftUI 原型，使用内存模拟音频后端。它不控制、采集或保存系统音频，也不是可发布的 SonaDeck 应用。

## 入口

- `Sources/PrototypeUI/App.swift`：macOS 15+ 原生 SwiftUI 窗口。
- `Sources/PrototypeModel/SimulationSession.swift`：跨平台模拟会话，复用 `../ProfileDomain` 的真实配置计划器。
- `Tests/PrototypeModelTests/`：20 次配置往返、规则释放、设备/权限阻断、失败重试、未运行应用、草稿与另存、序列化测试。
- [本轮测试报告](../../tests/reports/2026-10-09-windows-vm/report.md)：实际执行结果与截图，不能从源代码存在推断 UI 已通过验收。

## 运行与范围

在装有兼容 Swift 6 工具链的 macOS 15+ 上，从本目录运行：

```sh
swift run SonaDeckPrototype
```

需要标准 `.app` 外壳时，执行 `bash build-app.sh`，再执行 `open .build/SonaDeckPrototype.app`。脚本只做本地 ad-hoc 签名，不是 Developer ID 签名、公证或发布包。

模型测试可在带 XCTest 的 Linux / macOS 工具链中执行 `swift test`。本轮 macOS CLT 缺少 XCTest，补充验证使用[同源同步断言](../../experiments/windows-vm/README.md)，不等同于 XCTest。Linux 的可执行入口只输出平台限制提示；Linux 构建不会编译 `#if os(macOS)` 内的 SwiftUI 代码。

原型支持四套样例配置、整套模拟应用、增益/静音/输出草稿、会话内另存和可恢复草稿。选择配置始终应用已保存版本；恢复旧草稿必须显式点击“恢复草稿”，再应用。目标配置与模拟完整生效配置分开；缺设备、权限拒绝和注入执行失败不会改写先前实际状态。待生效应用不被标记为整套完成。

编辑后需点击“应用草稿 / 重试”，保存仅在当前会话有效。测试开关修改环境条件后需主动重试；尚未实现系统事件自动重协调、磁盘持久化、菜单栏、真实音频、完整双语和发布签名。该原型不替代正式产品需求。

## UI 人工测试矩阵

| ID | 操作 | 预期 |
| --- | --- | --- |
| UI-01 | 首次启动 | 空状态、模拟标识、禁用的应用/保存按钮清晰 |
| UI-02 | 工作与会议往返切换 | 应用行变化、旧独有规则释放，目标与模拟实际一致 |
| UI-03 | 编辑音量、静音和输出 | 草稿标记出现；应用前模拟实际规则不变化 |
| UI-04 | 另存配置再应用 | 原配置不覆盖，新增配置可直接选择；仅会话内保存 |
| UI-05 | 断开模拟 USB 后选择音乐 | 显示阻断与原因，实际仍为之前配置；连接后重试成功 |
| UI-06 | 关闭模拟权限后切换 | 保持之前实际规则，显示拒绝原因 |
| UI-07 | 注入下次执行失败 | 不假报成功，不修改实际；再次重试成功 |
| UI-08 | 关闭会议应用后选择会议 | 部分规则生效、会议待生效；整套不能显示成功 |
| UI-09 | 切换配置再返回修改中的配置，再显式恢复草稿 | 返回时先应用保存版本；恢复草稿不立即改实际；应用草稿后不能冒充保存预设 |
| UI-10 | 调整窗口、键盘导航、深浅色 | 无重叠和不可达操作；焦点和状态可辨；需 macOS 实测 |

所有 UI 项目必须通过真实 macOS 画面与交互验证。模型单测、HTML 日志截图和恢复系统截图均不计为 UI-01–10 通过。
