# 信息架构、页面与交互设计

更新日期：2026-09-30。状态：可用于下一步线框原型的设计规格，所有示例为虚构情境，不是实际天气。范围见[产品需求](product-spec.md)，权益见[广告设计](monetization.md)，算法语义见[预报方法](forecast-method.md)。

## 1. 导航与设计方向

底部三个入口：**Weather / 天气、Plan / 规划、Saved / 已保存**。设置从顶栏进入。默认回到上次查看的地点，但初次进入一定先呈现日常价值。地图是规划中的一种视图，不强制成为首页。

视觉方向为安静、可比较的天气工具：浅灰白背景、深色正文、蓝色主操作；橙色提示分歧，红色只用于官方警报或明确严重状态。天气好坏不用单独颜色编码。独立图标、品牌与布局，不照搬 Windy 的红色标识和专业面板。

正文默认 16sp、次要信息 14sp；触控目标至少 48dp；文字对比目标 4.5:1；支持系统大字体至 200%、TalkBack、浅/深色、减少动态效果。这些是验收目标，尚未测试。数字使用当地格式，单位可选 °C/°F、km/h/mph、mm/in；所有活动阈值随单位换算。

## 2. 页面清单

| 页面 | 回答用户的问题 | 主操作 | 免费/解锁与关键状态 |
| --- | --- | --- | --- |
| S01 添加地点 | 我要看哪里？ | 搜索、选择、可选当前位置 | 免费；无权限、重名地点、无网络、超出支持范围 |
| S02 天气首页 | 今天怎样？什么时候适合我出门？ | 看时段、保存、进入规划 | 免费；加载、缓存、缺失、预警、部分模型可用 |
| S03 当日/模型详情 | 为什么这样判断？ | 展开变量、模型与来源 | 免费；分歧、原生分辨率与未知独立呈现 |
| S04 规划编辑 | 我在什么条件下比较哪些选择？ | 日期、活动、地点、时长 | 编辑和覆盖检查免费；按权益运行完整比较 |
| S05 比较结果 | 哪个选择较合适，理由是什么？ | 选中、查看限制、保存 | 活跃权益可刷新；到期显示已保存快照 |
| S06 数周趋势 | 几周后大致怎么样？ | 切换周、比较区域 | 有覆盖才出现；未知与统计口径始终可见 |
| S07 奖励说明 | 看广告具体换什么？ | 首次试用/主动观看/返回 | 不出现模糊“高级版”；无库存、隐私不可请求、失败可退 |
| S08 已保存及变化 | 我的计划现在需要调整吗？ | 查看变化、复查、归档 | 免费基本跟踪；无基线、未到提醒时间、到期 |
| S09 设置与帮助 | 来源、隐私、单位如何控制？ | 更改单位、偏好、删除、隐私选项 | 无广告；数据来源、服务国家、诊断与奖励恢复 |

## 3. 首页线框

```text
Weather                         [地点] [设置]
Brighton · 当地时间                         示例
[官方预警/覆盖状态条：点击直接查看，不遮挡]

18°    当前预测 · 多云
预报更新于 10:20   [来源与模型]

你的户外时间
周六 10:00–12:00   可供考虑 · 模型有分歧
雨的影响较小；风的预测仍有分歧
[为什么]                          [保存计划]

[今天] [周六] [周日] …             日期可点选
小时温度 / 降雨概率 / 阵风         [文本表格]
未来天气                          [最多16天]

[比较其他地点]   [查看数周趋势]
Weather             Plan             Saved
```

“当前预测”不能标成现场实测。首页只展示一个最有用的窗口与一项主要限制，模型名称和变量详情展开后看。无可用窗口时显示“目前没有符合这些条件的连续时段”，提供调整偏好或日期，而不是强推广告。

没有起报时间时写“取得于”，不写成“模型更新于”。缓存过期有明确标识；不能把天气数据尚未加载显示成晴天或 0% 降雨。

## 4. 规划页与比较线框

```text
Plan · Weekend outdoors                    示例
日期 [周六]    当地时段 [09:00–18:00]
活动 [户外休闲]    持续 [2小时]
偏好 [查看/编辑]    地点 [A] [B] [+添加]
[列表] [地点地图]

候选地点 A      候选地点 B      候选地点 C
10:00–12:00     14:00–16:00     数据不足
更符合偏好      部分条件不符     缺少阵风
雨：…          雨：…          不参与排序
温度：…        温度：…
风：分歧较大    风：较一致
[选择 A]       [选择 B]        [查看原因]

比较覆盖：相同当地日期，各地本地时间
不确定性与来源 [展开]
[保存选择和比较快照]
```

用户先输入地点、日期和基本条件，系统完成覆盖检查，再提供完整比较的奖励入口。未解锁时显示真实地点与所需功能，不出现伪造的推荐、“已有更好答案”或模糊的真实温度卡。首次试用让用户体验实际比较结果。

地点地图只显示选中的候选地点、点击选点和相同口径的摘要。使用点数据时不填充连续颜色面，不伪装成全域气象场。平移地图不产生每像素天气请求；只有确认选择地点才查询。列表可独立完成全部任务。

跨时区默认按每个地点的本地日期、当地白天比较，顶端标注“各地当地时间”；此模式用于旅行而不是同一绝对时刻的直播比较。详情同时显示时区。夏令时重复小时用偏移区分，缺失小时不补造。

## 5. 远期页面

标题用“Weekly outlook / 周趋势”，副标题显示“用于提前筛选；无法确定某一天的天气”。从日历选择较远日期时自动跳到覆盖该日期的原生周区间，并说明“这里展示整周，非仅所选一天”。

每个周卡片包括完整日期区间、平均温度相对基准的倾向、累计降水相对基准的倾向、支持程度、来源和起报时间。日历上以周带表示，不填满太阳/雨点逐日图标。只有匹配口径的区间和变量才能跨地点比较。

偏暖不一定比另一地点更暖，偏干也不一定更少下雨。因此没有经过验证的绝对周温度/雨量信息时，界面只比较“相对各自常年的变化”，不输出“地点 A 最适合旅行”。不足以决策时主操作为“保存关注，临近再看”。

## 6. 保存与变化

保存页同时区分“当时的计划快照”和“最新情况”。免费允许看被选地点的当前天气、变化解释、删除或改名称；改变目的地、时间或偏好时创建一个新修订，不覆盖原始证据。使用默认偏好重新选择单地点时段依然免费；只有重新运行完整批量比较或自定义偏好才检查规划权限。

当计划进入短期范围，提醒用户“现在可以查看更具体的时段”。跨模型、跨预测产品变化不直接写为天气变化。例如由周趋势切到日预测，应标注“现在进入逐日预报范围”。

到期的是新的批量规划权限，不是用户已经获得的结果。已保存的比较快照可读，带生成时间且不会伪装成最新结果；被选地点的基础更新继续免费。

通知默认关闭。启用后，默认最多每日一次非紧急计划摘要，按地点时间避开用户设置的静默时段；推送不含“快看广告”，不因权益到期发送。官方预警与计划提醒分开。详见算法和隐私文档。

## 7. 广告前后文案

实际文案从奖励配置生成，以下采用当前设计参数；不可写死在多个页面。

| 场景 | 英语文案意图 | 中文释义 |
| --- | --- | --- |
| 奖励说明 | Watch an ad to unlock planning for 24 hours. Compare up to 3 places, adjust preferences, and explore available weekly outlooks. | 观看广告，解锁 24 小时规划；比较最多三个地点、自定义偏好、查看已具备覆盖的周趋势 |
| 次操作 | Continue with free weather | 继续使用免费天气 |
| 首次体验 | Try planning free for 24 hours | 免费体验完整规划，不先索取广告 |
| 广告不可用 | No ad is available. Your planning access is on us today. | 有覆盖且满足赠送规则时发放本次免费权益 |
| 获奖成功 | Planning unlocked until … | 显示具体到期时间和时区 |
| 模型分歧 | Forecasts disagree on the wind. Check again closer to departure. | 风的预测有分歧，临近出发再确认 |
| 无区分能力 | There is no clear weather advantage between these places yet. | 目前不能认为其中一个地点有明确天气优势 |

不得承诺广告固定 15 秒或 30 秒；时长受实际库存影响。SDK 提供结束与跳过方式时不遮挡，不要求点击广告、安装软件、购买或留下评价。不要用“支持我们才能继续”诱导选择。

## 8. 关键异常与无障碍

| 状态 | 处理与下一步 |
| --- | --- |
| 搜不到地点/同名 | 显示国家、行政区与小地图；可手动选点；不默认选第一项 |
| 未授权定位 | 保留搜索和收藏，系统拒绝后不循环弹框 |
| 支持范围之外 | 明示能力缺失；不展示无法兑现的奖励，不暗示无预警等于安全 |
| 网络断开 | 保留最近快照和时刻；可以编辑草稿，无法实时比较则明确排队/重试 |
| 三个模型只剩一个 | 显示来源数量，取消分歧判断；不写“一致” |
| 候选之一缺字段 | 单独标记未知，不补零；允许从已满足覆盖条件的候选继续 |
| 没有周趋势 | 说明未开放原因，保留短期规划；不显示锁图标来掩盖缺数据 |
| 广告取消/完成后失败 | 按奖励状态机处理，输入和页面滚动位置保留 |
| 系统杀进程/横竖屏 | 恢复草稿、保存结果及奖励收据；不要求重复观看已完成的广告 |
| 大字体/读屏/键盘 | 比较表转换为逐地点卡；图表有文本表格；不用仅滑动或颜色传达关键结论 |
| 减少动态效果 | 取消装饰动画，时间轴可按钮步进；回到后台暂停动画 |

## 9. 原型场景与完成条件

下一轮交互原型至少包含：免费单地点成功、三地点首次试用、主动广告成功、广告无库存、奖励恢复、远期无法区分、已有计划天气变化、断网、读屏表格。每个页面标注模拟数据和未接入服务。

线框通过条件是用户能完成 J1/J2/J3、复述奖励与远期含义，不是页面看起来像成熟竞品。性能、研究阈值和可访问性检查见[验证计划](validation.md)。本轮交付文档与线框规格，未生成可运行界面。
