# 用户选择、预报质量与广告模式验证

更新日期：2026-09-30。状态：待执行。所有目标是预先约定的设计门槛，不是已达到指标。验证对象是用户选择与可持续服务，不以功能数量或广告展示量代替价值。

## 1. 核心指标与事件

北极星候选：**每周完成并在活动前回访的有效计划数 / 周活跃用户**。一个有效计划要求用户选定时间地点、查看过理由并明确保存；同一计划反复编辑、分享、刷广告不重复计数。回访是查看最新条件或变化，不是通知曝光。

| 事件 | 用途 | 最小记录 |
| --- | --- | --- |
| basic_forecast_viewed | 基础可用性 | 是否有完整数据、缓存/在线、加载时长桶 |
| planning_started | J1/J2 漏斗 | 单地点/多地点/周趋势、是否首次，不上传坐标 |
| explanation_opened | 理由是否被使用 | 理由类别，非实际行程内容 |
| plan_saved | 完成任务 | 随机计划引用、同意后的匿名关联、任务类型 |
| plan_revisited / change_viewed | 复用与提醒价值 | 距活动的时间段、变化类型、是否主动打开 |
| reward_offer_viewed / declined | 奖励理解与意愿 | 配置版本、可用功能集 |
| ad_requested / impression / reward_earned | 广告供给与发放 | 广告会话引用，实际获奖与收入分开 |
| grant_delivered / recovered / failed | 兑现可靠性 | 试用/广告/赠送/补偿、错误类别 |
| result_unavailable | 没有结论的原因 | 缺数据/分歧/范围/故障，不能简单算成功结果 |

原型研究以明确招募和同意为前提；生产分析按真实国家规则和隐私设计启用。未同意分析的用户也能使用基本服务；统计报告需披露覆盖偏差。不会为了指标而强制点击“我已理解”。

## 2. 用户选择实验

先做 12–16 人的形成性测试，均有真实的周末户外/短途出行习惯；分别包含 Windy/同类使用者和普通天气用户。不用朋友称赞替代测试。当前未招募、未向外部用户发送消息。

交叉顺序比较我们的线框与用户现用工具，再安排至少一种强替代品：Ventusky/Flowx 验证地图用户，VeriSky 验证模型和活动规划用户。不能只选择功能弱的基线来证明优势。任务采用相同地点和日期，但使用真实 App 时要记录数据起报差异，不能将输出不同误算作 UI 优劣。

| 任务 | 观察 | 首轮继续迭代门槛（规划默认） |
| --- | --- | --- |
| J1 单地选择活动时间 | 是否找到窗口、能否解释限制、免费是否完整 | ≥80% 不求助完成；中位耗时比个人现用流程减少 ≥25% |
| J2 三地选择 | 是否理解时间口径、能否处理无法区分 | ≥80% 完成保存或明确判定证据不足；不迫使人人选出胜者 |
| J3 查看变化 | 能否区分快照与最新，知道是否要重新考虑 | ≥80% 正确说明变化含义；不得把数据源切换误认为天气突变 |
| 数周趋势理解 | 能否解释偏暖/偏干、日期范围与不确定性 | ≥90% 能说明不是指定日期的天气保证；严重误解一律回改文案 |
| 广告承诺理解 | 能否说明范围、到期和取消影响 | ≥90% 正确复述；奖励兑现严重故障为零容忍发布阻断 |
| 自主选择 | 完成测试后愿选什么工具，为什么 | ≥60% 愿在下次真实任务主动用本产品，且理由包含规划价值而非仅“免费” |

小样本门槛是设计筛选，不是统计显著性声明。报告原始人数、分母、失败案例和已有产品偏好；不把 8/12 的选择外推成市场份额。

随后做 4 周、至少 30 名有效参与者的自愿日记测试，记录计划频次和主动回访。目标：至少 40% 激活用户在后续一周再次完成/复查真实计划；这些比例需分用户是否有活动，避免用不出门的人反推界面失败。未达到时先检查任务频次与实用性，再调整定位。

## 3. 广告实验

| 阶段 | 能证明 | 不能证明 |
| --- | --- | --- |
| 文案/可点击原型 | 是否理解交换、是否愿意尝试 | 真实等待后的流失、广告填充、收入 |
| SDK 测试广告 | 奖励状态、取消、恢复、重复回调 | 真实广告内容、地区 eCPM 与商业可行性 |
| 小范围真实库存 | 完成率、展示净收入、故障与赠送成本 | 全球所有国家和季节的盈利能力 |

首轮真实试点门槛：广告前已有规划意图的人中 ≥30% 自愿选择；展示后奖励完成率目标 ≥75%；相对首次无广告试用组，任务完成率绝对下降不超过 10 个百分点。展示后的感知体验必须访谈，不只看漏斗。上述数值是可修改的规划标准，改动须在分析之前记录。

经济试点至少覆盖四周，按国家/同意状态拆分展示、完成、赠送、试用与成本；样本不足不宣布盈利。预算使用净结算收入和全部服务成本，具体公式以[商业设计](monetization.md)为准。进入扩大投放的门槛是保守情景下月服务收入/成本 ≥1.3，另列人工与获客后是否可持续。

若需要每天多次强迫观看才打平，当前方案不通过。若用户价值成立而广告不成立，保留产品结论、重新讨论商业方式；不要用更糟的广告体验掩盖成本。

## 4. 数据与预报验证

既有[接口实验](../experiments/README.md)只证明连通和部分覆盖。本轮未运行新气象实验、未创建准确率成绩。

### 数据完整性

建议对首发研究区域至少 12 个位置连续保存 8 周，包含城市、海岸、内陆和高差情境。记录所有起报和失败，不只保留有数据样本。接口可用率与覆盖率分开：HTTP 200 不等于指定小时和变量齐全。

进入可用性测试的技术目标：请求成功率 ≥99%，目标范围关键变量有效覆盖 ≥98%，明确来源和时效；样本与供应商条件需报告。若个别模型不足，可降级来源数量，但不能隐藏不支持的功能来虚报总体成功。

### 科学质量

- 短期：对独立站点观测检验温度偏差/MAE、降水与风，按提前量和地形分层；观测质量控制和网格代表性单列。
- 活动窗口：用用户阈值对预报和观测分别计算结果，统计“推荐但实际不符合”与漏掉可用窗口；同时报告原始天气误差和偏好规则的影响。
- 周趋势：使用匹配模式气候基准及独立验证期，分第 3/4 周、变量、季节和地区；概率可用 Brier/可靠性，分布可用 CRPS，确定性周量可用误差；不能混成一个“30 天准确率”。
- 样本存在相关性：重叠周、相邻网格和相邻起报不能当独立样本；用按时段分块的不确定区间或合适重采样方法，训练与验证按时间隔离。
- 长期正式开放前需要跨季节回报数据或足够长期的前瞻样本。8 周只能发现管道问题；不支持年度预测技巧结论。

远期功能的生产门槛：授权和统计口径清楚；在目标地区与变量的预注册评价中，相对对应气候基线具有可解释增益，且不确定区间不支持明确负增益。未能排除零增益时仅作标明未验证的研究结果，不以“更好决策”对外促销。若只有温度通过，奖励只包含温度趋势，不能连带声称雨量通过。

方法参考与来源见[数据源调研](data-source-research-2026-09-28.md)和[预报规格](forecast-method.md)。这些门槛为项目质量要求，不是供应商保证。

## 5. 功能与性能验收

| 范围 | 必测场景 | 通过条件 |
| --- | --- | --- |
| 免费流程 | 无权限/拒绝广告/拒绝分析/断网重开 | 有缓存则可读，没缓存明确失败；没有无意触发广告 |
| 预报算法 | 缺值、重复源、单位、累积区间、D0、DST、周边界 | 满足[测试向量](forecast-method.md)；不生成伪概率或虚假确定结论 |
| 权益 | 取消、完成、重复与迟到 SSV、旋转、杀进程、离线、回拨时钟 | 符合[权益规则](monetization.md)，同一奖励不丢失、不重复增长 |
| 变化与提醒 | 修改计划、版本变化、重复起报、静默时段、关闭通知 | 不误报、去重、可退订；到期不停止基本跟踪 |
| 可访问性 | TalkBack、200% 字体、键盘、深色、色觉与减少动画 | 全部主要任务可完成，图表有等价文本 |
| 删除与隐私 | 删除计划、关闭提醒、清数据、隐私选项 | 删除/停止上传与文案一致；广告参数不包含行程 |
| 服务故障 | 广告/地图/预警/天气分别超时 | 局部降级、来源可查；数据缺失不伪装成无雨或无警报 |

性能预算（待测）：中档 4GB Android 真机，稳定 4G、约 100ms RTT；有缓存的首页可交互 p95≤1秒，网络更新 p95≤3秒；三个地点比较 p95≤5秒（有上游缓存）。记录冷/热启动和上游缓存未命中，不能只报告平均值或模拟器结果。无缓存超过预算有可取消加载与说明，不能假装已完成。

滚动目标接近 60fps，关闭后台装饰动画；通过实测帧耗时、峰值内存和相同任务耗电比较，不在设计阶段宣称流畅或省电。首次地图不应阻塞列表。

| 产品理由 / 需求 | 设计位置 | 验证方式 |
| --- | --- | --- |
| 快速选时间 F01–F04 | 体验 S01–S03、时段规则 | J1、单位/缺值/DST 用例 |
| 比较地点 F05 | 体验 S04–S05 | J2、与强替代品交叉测试 |
| 远期有正确预期 F06 | 体验 S06、周统计规则 | 理解测试、基线技巧验证 |
| 保存与回访 F07/F09 | 体验 S08、快照与变化 | J3、4 周日记、误报率 |
| 自愿交换 | 体验 S07、权益状态机 | 广告理解、恢复测试、净收入 |
| 可信基础体验 F08/F10/F11 | 预警、组件、分享规格 | 过期、覆盖、来源和辅助功能验收 |

每次验证报告必须写：版本、环境、样本及选择偏差、时间范围、原始数据入口、通过/失败、尚未回答的问题、下一项动作。原型喜好不能代替留存，实际广告收入不能代替气象质量。
