# 预报语义、活动窗口与变化解释

更新日期：2026-09-30。状态：实现前规则规格；阈值均为规划默认，未经用户偏好或气象效果验证。本文定义统计口径与算法，产品不能用广告权益改变这些语义。

## 1. 四种信息必须分开

| 信息 | 产品允许表达 | 禁止推论 |
| --- | --- | --- |
| 观测 | 某站点某时刻测得，附位置、高度/代表性限制 | 当前模式值称为现场实况 |
| 单一预测 | 某模型对未来时刻的预测，附起报时间 | 单一轨迹代表必然发生 |
| 跨模型分歧 | 几个可比较的模型对同一变量的预测差异 | 三个模型两个下雨，便称真实降雨概率 67% |
| 集合/周统计 | 成员分布、官方概率产品、匹配气候基准的周距平 | 集合区间必然覆盖实况；偏干便等于不下雨 |

服务端字段区分 `observation`、`deterministic`、`ensemble_statistic`、`weekly_anomaly`、`provider_probability`。基础版本先用预测，不为模拟“实况”补造观测。

## 2. 时间范围与切换

`D0` 是所选地点当前本地日期；“首 7 天”为 D0–D6，“最多 16 天”为 D0–D15，“约一个月”计划选择为 D0–D29。日期可选不保证每个源完整覆盖。所有取样按真实时间戳计算，D0 不把已经过去的小时算成未来活动窗口。

| 范围 | 默认展示 | 计算约束 |
| --- | --- | --- |
| D0–D6 | 小时天气、活动时段、模型分歧 | 只在所需变量与时段完整时给窗口建议；不把 3 小时源插值包装成独立小时预测 |
| D7–D15 | 逐日参考、范围、来源差异 | 不运行小时活动窗口；跨地点比较以日统计和日期为单位 |
| D16–D29 | 覆盖选择日期的原生完整周趋势 | 不输出精确活动时段、逐日雨图标或一天出游推荐 |

边界是产品设计，不是对全球预报技巧的统一判断。即使在 D0–D6 也可能高度不确定。周产品可跨 D29，必须展示其完整日期，并标注用户选择仅占其中一部分；不得裁掉几天后继续称为原生周统计。

ECMWF 的次季节目录提供最长 46 天的集合与周统计产品，包含均值、距平及概率；这支持周趋势设计，不证明具体城市第 30 天准确。[官方产品目录，2026-09-30 核验](https://www.ecmwf.int/en/forecasts/datasets/set-vi)

## 3. 统一数据与来源

每条数据至少记录：供应商、真实上游模型/版本（可得时）、产品类型、起报时间及其是否未知、抓取时间、有效时间/区间、地点时区、网格位置/尺度、单位、时间步长、统计对象、缺失标记、授权及署名、变换版本。

起报时间、抓取时间与用户保存时间是三个字段。缺起报信息时保留 null，不用抓取时刻填充。所有单位先转标准单位计算，最后按偏好显示；缓存键不能把不同日界线混为一项。

第一阶段候选为 ECMWF IFS、GFS、ICON，通过授权聚合服务接入；同一供应商的 best-match 或混合源不能未经追溯就算成第四个独立模型。不强求各模型覆盖同样远，缺覆盖时减少数量并明示，不能通过拼接冒充一个模型。

数据新鲜度默认按源预期更新周期：超过一个周期加 2 小时标记延迟，超过两个周期加 2 小时退出活动推荐，仍可查看带日期的历史参考。更新周期无法取得时不猜“最新”，该源先不用于自动推荐。此容忍量需通过连续采样调整并版本化。

## 4. 可比较性与分歧

比较前统一变量定义、时区、累计区间和单位。例如平均风不能与阵风求同一个范围，降水概率不能与雨量相减，过去 3 小时累计不能当下一小时值。

只有至少两个可追溯、非重复的模型在同一变量和时间区间有有效值时才计算分歧。两个或三个确定性值只显示模型范围及数量，不称 80% 置信区间。缺失或过期模型不视为同意。

首期最有用的分歧是“模型对用户阈值是否给出不同判断”。例如风预测分别低于、高于用户设置阈值，则显示“风的预测分歧会影响你的计划”；不用一个拍脑袋的全局可信度百分数。

解释轴分为：来源是否足够、模型是否一致、预报距离多远、数据是否新鲜。不要将它们平均成“准确率 92%”。各模型彼此一致也不代表一定准确。

## 5. 活动时段算法

初版默认模板仅是偏好起点，页面允许查看具体阈值：

| 模板 | 温度 | 小时降水量 | 平均风 / 阵风 | 默认连续时长 |
| --- | --- | --- | --- | --- |
| 户外休闲 | 10–28°C | ≤0.2 mm/h | ≤20 / ≤30 km/h | 2 小时 |
| 休闲骑行 | 8–26°C | ≤0.2 mm/h | ≤15 / ≤25 km/h | 2 小时 |
| 自定义 | 用户明确选择，继承模板并逐项可改 | 用户设置 | 用户设置 | 用户设置 |

这些不是安全限值；不适用于专业运动、山地与海上条件。降水量阈值不是降雨概率。展示供应商概率时另列来源和事件定义，不由这些阈值产生。

确定性流程如下：

1. 在用户选定的当地时段内，只保留尚未经过且数据新鲜的整点窗口。长度按真实经过时间计算，避免夏令时错误。
2. 对每个候选模型，要求所需温度、降水量、平均风和阵风在整个窗口都有适用的原生小时值；缺一个必要变量则该模型不能给完整通过判断。
3. 每个模型对每个小时执行用户阈值判断，再合并为连续窗口。模型内部所有小时/条件都通过，才称此模型支持该窗口。
4. 先检查完整模型是否至少两个；不足则标记“信息不足”。其余情况中，所有完整模型都支持才标记“更符合这些偏好”；有支持也有反对则标记“预测有分歧”；全部不支持则标记“未符合”。原始天气仍可免费查阅。
5. 先列支持一致的窗口，再列有分歧的参考窗口。相邻或重叠的窗口合并呈现，最多展示三个；同级按用户选定起始时间的距离排序，不暗示气象效果存在统计显著差异。
6. 给出主要限制因素和可替代日期。条件过严而无结果时明确说明，不偷偷放宽阈值。

以上是规则引擎，不是新天气模型。无合格小时输入时可提供逐时/逐日参考，但不运行同样精度的活动推荐。后续是否采用集合决策概率，需单独验证。

官方严重预警与偏好结果分层显示：当支持地区有相关预警覆盖时，显著显示官方内容，暂停正向“推荐”措辞，保留数据供查看。预警接口不可用显示未知，不能以空列表推论没有预警。没有权威源或时效可靠性时不宣传安全保障。

## 6. 多地点比较与远期规则

短期多地点使用相同模板、持续时间和可比变量；逐日比较显示日最高/最低温、累计降水、风等真实定义，不把小时窗口算法用于日均值。数据不足的地点单列，不补零、不降权后悄悄排到第一名。

远期默认直接采用经授权、含匹配基准说明的周统计。必须保留周起止、模式气候基准、变量及统计对象。比较方向与绝对条件分开：两个地方同为“偏暖”不说明气温相同；有可靠绝对周均值才可同列，仍不能当每日最高温。

没有正式校准的成员统计，只能表述为“有效成员中 X/Y 支持此方向”，并提示非校准概率；首期首页默认不显示自算概率。没有基准/足够覆盖，不显示“偏暖/偏干”。只有原始成员 API 通了而未建立统计验证，不足以开启生产 F06。

不自动把独立模型平均成“最准”预测，不用语言模型填补缺失，不输出长时效地点胜率。只有在样本和质量门槛通过的地区/变量开放对应周趋势；其他地区明示未提供。

## 7. 保存基线与变化提醒

每次计划修订保存地点、时段、阈值、支持模型、实际预测快照和规则版本。默认比较对象是用户上次明确保存的同一修订；另外保留上次已通知的状态以抑制重复提醒。

首次保存无历史可比，显示“从现在开始跟踪”。不能事后请求今天的回溯数据冒充用户保存时的预测。变更数据源、模型、统计产品或规则版本时提示“比较口径变化”，不直接算作天气变化。

规划默认仅在以下事件触发普通计划提醒：同口径下由符合偏好变成有分歧/不符合，反向恢复，或被选时段因新数据不再完整。单次变化需连续两个新起报周期确认；官方预警通过独立流程及时展示，不等待这一防抖。

同一计划按当地日期最多一次普通提醒，聚合进每日摘要；用户可静音、关闭和删除。进入活动前 48 小时才默认启用天气变化提醒；更早只在用户主动复查时展示。周趋势进入逐日范围的解释只发送一次。

## 8. 原则性测试向量

| 输入情境 | 预期行为 |
| --- | --- |
| 两模型全时段符合、第三模型超风阈值 | “有分歧”，不输出三分之二成功概率 |
| 一个模型完整、另两个缺阵风 | 天气仍可看；窗口标“信息不足” |
| 温度用 °F、用户切换 °C | 物理阈值不变，排序不因单位变化 |
| 三小时雨量/小时雨量混合 | 未统一时段前不直接比较或计算小时窗口 |
| D0 已过半、跨夏令时两小时活动 | 不选过去时刻；持续时间是实际两小时 |
| 周数据跨目标日期/月份 | 显示完整原生周界，不截成伪逐日天气 |
| A 偏干但常年很湿，B 偏湿但常年很干 | 不因距平符号推荐 A 更少雨 |
| 同模型两供应商、best-match 与其上游 | 不重复计入独立支持数 |
| 数据相同但解析/规则版本改变 | 标记口径变化，不发天气恶化提醒 |

这些是未来自动化测试要求，本轮仅设计，未声称算法已经实现或通过测试。
