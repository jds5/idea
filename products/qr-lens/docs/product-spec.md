# 产品需求

## 用户已确认

- 开发 Chrome 插件，解析二维码并给出字符串。
- 点击插件后以透明遮罩覆盖页面，分别识别画面中的二维码。
- 支持截图式框选；用户框选后仅展示选定区域的二维码结果。
- 复制解析结果与框选操作不能冲突。

## 首期实现默认

- 产品工作名 QR Lens，名称尚未由用户确认。
- 「页面」指点击时当前标签页的可见视口，以截图固定坐标；不自动滚动采集整张长网页。
- 每个可识别位置对应一个结果；相同字符串在不同位置仍单独显示。编号、位置标记和结果顺序对应。
- 原始字符串仅作为文本显示，保留中文、空格、换行；HTML 不执行，URL 不自动打开。
- 选区只包含整个二维码边界完整位于选区内的结果，不采用仅相交即纳入。反向拖动有效；小于 8 CSS 像素的拖动不改变选区。
- 仅背景选择层处理框选指针事件；结果面板、文本框、复制按钮、工具栏不参与框选。面板可以收起，以选择其遮挡的区域。
- 支持恢复全部、Esc 退出、键盘框选、可见焦点、无结果和错误提示。关闭后恢复原有焦点。
- 仅用户主动点击时访问当前页，不申请全站常驻权限。处理在本机，截图不落盘、不上传，关闭界面和请求完成后释放引用。

## 工程边界

- 截图最长边最多 4096 像素、总量最多 1200 万像素；后台依次识别、遮去已解码符号，辅以重叠分块扫描。
- 每轮最多 64 个二维码，扫描预算 10 秒，在单次解码调用之间检查；这是保护上限，不是已验证的性能承诺。达到上限时必须显示结果可能有遗漏。
- 框选是对本轮已识别结果进行空间筛选，不重新拍摄或对选区进行额外解码。小码可通过放大网页后重新识别改善。
- 不承诺二维码全部识别成功；模糊、遮挡、过小、变形、密集排列或特殊编码可能导致遗漏。
- 不支持 Chrome 禁止脚本注入的页面。文件 URL 访问由 Chrome 的单独开关控制。
- 默认中文界面；最低版本 API 目标 Chrome 109，实际最低版本兼容仍待验收。

## 延后

长网页自动拼接、图片文件导入、摄像头、其他条码、历史记录、自动打开链接、云端识别、多语言界面、商店发布。
